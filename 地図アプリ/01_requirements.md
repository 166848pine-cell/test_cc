# PinRoute 要件定義書 v1.0

## 1. 背景・目的

- 複数の住所・施設をまとめて地図上にピンとして配置し、名称を付け、巡回ルートを即座に確認したいという個人ニーズがある(内見・訪問先の下調べ、外出計画など)
- 既存地図サービスでは「複数地点の一括登録+自由な名称+並び替え+ルート即表示」を1画面で完結できない
- 開発者(発注者)の方針:**運用コスト・維持費ゼロ**。無料APIのみ、静的ホスティング、サーバー不要。将来的に広告(AdSense)を貼れる余地を残す

## 2. スコープ

### 2.1 対象(v1)

| ID | 機能 | 概要 |
|---|---|---|
| FR-01 | 地点検索 | 住所・施設名のテキスト入力から座標を取得(国土地理院API→Nominatimの順でフォールバック) |
| FR-02 | 候補選択 | 検索結果が複数ある場合、上位最大5件を候補表示し、利用者が選択して確定する。1件のみなら即確定 |
| FR-03 | ピン表示 | 確定地点を地図上に番号付きマーカーで表示。番号は一覧の並び順と常に一致 |
| FR-04 | 名称編集 | 各ピンの名称を一覧上でインライン編集できる。初期値は検索結果の名称 |
| FR-05 | 並び替え | 一覧のドラッグ&ドロップおよび▲▼ボタンで順序変更。ルートは順序に追従して再計算 |
| FR-06 | 削除 | 個別削除および全削除(全削除は確認ダイアログあり) |
| FR-07 | ルート表示 | ピンが2件以上のとき、登録順に結ぶ**車ルート**を自動描画。総距離(km)・総所要時間(分)を表示 |
| FR-08 | 外部連携 | 現在のピン順序でGoogleマップの経路検索を開くリンクを表示(公共交通・徒歩はこちらで代替) |
| FR-09 | 永続化 | ピン一式をlocalStorageに自動保存し、再訪時に自動復元 |
| FR-10 | 共有URL | ピン一式をURLフラグメントにエンコードした共有URLを発行。URLを開くと同じ状態を復元(サーバー不要) |
| FR-11 | レスポンシブ | PC(2ペイン)とモバイル(縦積み)の両対応。モバイル幅375pxで全機能操作可能 |

### 2.2 対象外(v1では実装しない)

- 巡回順の自動最適化(TSP)
- 徒歩・自転車・公共交通のルート計算(FR-08のGoogleマップリンクで代替)
- ユーザー登録・ログイン・サーバー側保存
- 地図上クリックによるピン追加(v2候補)
- 多言語対応(日本語UIのみ)
- 広告の実装(枠のみレイアウトに確保。§4.5)

## 3. 利用者・利用環境

- 想定利用者:一般個人(日本国内の住所検索が主用途)
- 対応ブラウザ:Chrome / Safari / Edge の最新版、iOS Safari
- ネットワーク:オンライン必須(地図タイル・API通信のため)

## 4. 非機能要件

### 4.1 コスト・構成制約(最重要)

- **NFR-01**: 使用APIはすべて無料・APIキー不要であること。具体的には 国土地理院ジオコーディングAPI / Nominatim / OSRMデモサーバー / OpenStreetMapタイル のみ
- **NFR-02**: 静的ファイルのみで動作し、GitHub Pagesにそのまま配置できること
- **NFR-03**: ランニングコスト0円(ドメイン等の任意費用を除く)

### 4.2 外部サービス利用規約の遵守

- **NFR-04**: Nominatimへのリクエストは1秒1回以下にスロットリングする
- **NFR-05**: OSMタイル・Nominatim・国土地理院・OSRMの帰属表示(attribution)を画面上に常時表示する
- **NFR-06**: OSRMデモサーバーは稼働保証がない前提で設計し、失敗時は利用者に分かる形で通知しつつピン機能は継続動作させる(グレースフルデグラデーション)

### 4.3 性能・信頼性

- **NFR-07**: 地点検索は入力確定から3秒以内に候補表示(API応答遅延時はローディング表示)
- **NFR-08**: ルート再計算は連続操作時にデバウンス(500ms)し、多重リクエストを抑止する
- **NFR-09**: API失敗時もアプリがクラッシュせず、日本語のエラーメッセージを表示する(詳細は詳細設計のエラー処理表)

### 4.4 プライバシー・セキュリティ

- **NFR-10**: 利用者データ(ピン情報)はlocalStorageとURLフラグメント以外に保存・送信しない
- **NFR-11**: 検索クエリが外部API(国土地理院・Nominatim・OSRM)に送信される旨をフッターに明記する
- **NFR-12**: 名称等の利用者入力は表示時に必ずエスケープし、XSSを防止する

### 4.5 将来拡張の余地

- **NFR-13**: 画面下部(モバイル)/パネル下部(PC)に広告用プレースホルダ領域(高さ可変、初期は非表示)を設け、後日AdSenseコードを1ファイルの差し替えで挿入可能な構造にする

## 5. 制約・前提

- 開発者は保守に時間を割けない前提。依存パッケージは最小限にし、ビルドが単純であること
- ピン件数の上限は20件(OSRMデモサーバーへの負荷配慮とURL長制約のため)。上限到達時はメッセージ表示
- 共有URLの長さがブラウザ実用限界(目安2,000文字)を超える場合は発行時に警告する

## 6. 受け入れ基準(抜粋)

1. 「東京駅」「大阪市北区梅田1丁目」等の入力でピンが立つ
2. 3地点登録時、地図上にルート線・総距離・総所要時間が表示される
3. 並び替え後3秒以内にルートが新順序で再描画される
4. ブラウザ再起動後、前回のピンが復元される
5. 共有URLを別ブラウザ(シークレットウィンドウ)で開くと同一のピン・ルートが再現される
6. ネットワーク遮断状態で操作してもクラッシュせず、エラーメッセージが表示される
7. 詳細な合否判定は `04_test_spec.md` の全テストケースPASSをもって完了とする
