# PinRoute

住所・施設名をまとめて地図にピン留めし、並び替えて巡回ルート(車)の距離と所要時間をすぐ確認できるWebアプリ。
物件一覧の表を貼り付けて一括登録し、地図上に引き出し線つきの情報ブロックとして並べることもできる。

- サーバー不要・APIキー不要・ランニングコスト0円
- 静的ファイルのみ。`dist/` をそのままGitHub Pagesに置けば動く
- ピン情報はブラウザのlocalStorageと共有URL以外には保存されない

## 開き方

**`dist/PinRoute.html` をダブルクリック**するのが一番かんたんです。JSとCSSを1枚に畳んであるので、
サーバーを立てずにそのまま動きます。

`index.html`(リポジトリ直下)や `dist/index.html` を直接開いても**動きません**。
ブラウザは `file://` のページから別ファイルのスクリプトやCSSを読み込むことをCORSで禁止しているためです。
画面は出ますが地図が表示されず、検索しても反応しません。

資料はすべて `docs/` にあり、ダブルクリックで開けます。

| ファイル | 内容 |
|---|---|
| `docs/manual.html` | 図解付きの操作手順(使い方) |
| `docs/how-it-works.html` | 仕組みの解説(フォルダ構成・ビルド・GitHubで公開できる理由) |
| `docs/git-and-github.html` | GitとGitHubのきほん(初学者向け図解) |

## 使い方

1. 住所や施設名を入力して「検索」(Enterでも可)
2. 候補が1件に絞れればそのままピンが立つ。複数あれば所在地つきで候補が出るので選ぶ(↑↓とEnterでも選べる)
3. ピンが2件以上になると、登録順に結ぶ車ルート・総距離・所要時間・区間ごとの距離が自動表示される。
   ルートが不要なときは「車ルートを表示する」のチェックを外す(外している間はルート計算も行わない)。
   Googleマップのリンクはルート表示に関わらず、2件以上あれば使える
4. 一覧のドラッグ(左端のグリップ)または ▲▼ で順序を変更するとルートが再計算される
5. 「共有URLをコピー」で、そのままの状態を再現できるURLが得られる(サーバーには何も保存されない)

### まとめて入力と情報ブロック

物件名・住所・駅徒歩・賃料などの列が並んだ表を、Excelやスプレッドシートから
そのまま貼り付けて一括登録できる。

1. 「まとめて入力」に表を貼り付ける。住所の列と名称の列は見出しから自動で選ばれる
2. 「取り込む」で住所を1件ずつ調べてピンを立てる。見つからなかった行は理由つきで残る
3. ピンから引き出し線が伸び、その先の情報ブロックに表の内容が並ぶ
4. ブロックは見出しをつかんでドラッグすると好きな位置に置ける(位置は保存される)
5. 「情報ブロック」で表示する項目と順番を変えられる。「すべて表示」「すべて隠す」でまとめて切り替えも可能
6. 「見た目」でピンとブロックの色・大きさを変えられる。全体をまとめて変える設定と、
   ピン一覧の各行にある丸いボタンから地点ごとに変える設定の2段構え

ブロックの初期位置は自動で決める。余裕があればピンのすぐ横に、
駅の徒歩圏に集まって置ききれないときは地図の左右の端に振り分けて縦に並べる。
ドラッグしたブロックは自動配置の対象から外れ、その位置を保つ。
1つ動かしたときに他のブロックが動かないよう、そのとき自動配置だった分もあわせて位置を確定する。

試すためのサンプルとして `docs/sample-properties.csv`(神保町駅から半径500m以内の10件)を同梱している。
住所は実在の街区、物件名・賃料・面積は説明用の架空の値。

## セットアップ

```bash
npm install
npx playwright install chromium   # E2Eテストを実行する場合のみ
```

Node.js 20以上を想定。

## 開発

```bash
npm run dev        # 開発サーバー (http://localhost:5173)
npm run build      # 型チェック + 本番ビルド → dist/ と dist/PinRoute.html
npm run preview    # ビルド成果物をローカル配信
npm run manual     # 操作マニュアル docs/manual.html を実画面から生成
npm run lint       # ESLint
npm run format     # Prettier
```

`npm run build` は2つの成果物を作る。

| 成果物 | 用途 |
|---|---|
| `dist/index.html` + `dist/assets/` | GitHub Pages などに配置する通常版 |
| `dist/PinRoute.html` | JS/CSSを埋め込んだ1ファイル版。ダブルクリックで開ける・そのまま人に渡せる |

## テスト

```bash
npm run test       # 単体(UT) + 結合(IT) — Vitest + happy-dom、fetchはモック
npm run test:e2e   # E2E — Playwright(chromium / 375pxモバイル)、外部APIはスタブ
npm run smoke      # 実ブラウザ + 実APIでの疎通確認(下記)
```

E2Eはルート計算を含めて検証するため、`VITE_ROUTING=on` でビルドした `dist-e2e/` に対して実行する。

`npm run test` と `npm run test:e2e` は外部サーバーに一切接続しない。
CIや繰り返し実行で国土地理院・Nominatim・OSRMに負荷をかけないため。

### `npm run smoke` について

モックだけで固めると「テストは全部通るのにアプリは使い物にならない」状態を見逃す。
実際にこのアプリでは、全35テストがPASSしている状態で
**検索するとまったく無関係な地点がピンになる**という不具合が残っていた
(原因は後述の「検索の仕組み」)。

そこで実ブラウザ・実APIで次を確認するスクリプトを用意している。

```bash
npm run build
npx vite preview --port 4173 --strictPort   # 別ターミナルで起動しておく
npm run smoke
```

確認内容:

- 代表的な検索語(東京駅 / 大阪市北区梅田1丁目 / 札幌市時計台 / 横浜駅 / 名古屋城 / 六本木ヒルズ)で、期待した地点が先頭に来るか
- 各検索が3秒以内に終わるか(NFR-07)
- 3地点の実ルートで常識的な距離・所要時間・区間表示が出るか
- 公開ビルドがOSRMに接続せず、地理院タイルを使っているか
- 同じ言葉の再検索で外部に問い合わせ直さないか(キャッシュ)
- 帰属表示が画面に出ているか(NFR-05)
- モバイル375pxで横スクロールが出ないか
- コンソールエラー・リクエスト失敗がないか

`.smoke/desktop.png` と `.smoke/mobile.png` にスクリーンショットも出力される。

## 公開する

### ビルドは2種類ある

`npm run build` は用途の違う2つの成果物を作る。**外部サービスの利用規約に合わせて中身が違う**。

| 成果物 | ルート計算 | 用途 |
|---|---|---|
| `dist/`(index.html + assets) | **なし** | 一般公開用。GitHub Pages などに配置する |
| `dist/PinRoute.html` | あり | 手元で使う1ファイル版。ダブルクリックで開ける |

ルート計算に使っているOSRMのデモサーバーは、提供元が
「非商用かつ合理的な用途に限る」と定めており**公開アプリからの利用を認めていない**。
そのため一般公開するビルドではルート計算を外し、経路は「Googleマップで開く」で代替している
(通常のリンク遷移でAPIではないため、利用制限がない)。

切り替えは `VITE_ROUTING` 環境変数で行う(`.env` / `.env.standalone`)。

### GitHub Pages(自動)

`.github/workflows/deploy-pinroute.yml` を用意してある。

1. リポジトリに push する(`main` ブランチ、または画面から手動実行)
2. GitHub の **Settings → Pages → Source** を「**GitHub Actions**」にする
3. 公開URL: `https://<ユーザー名>.github.io/<リポジトリ名>/`

ワークフローの中で lint とテストを通してからビルドする。`dist/` はコミットしない。
`base: './'` を指定しているため、サブディレクトリ配信でもそのまま動く(実機確認済み)。

### そのほかの方法

| 方法 | 手順 |
|---|---|
| Netlify Drop / Cloudflare Pages | `dist` フォルダをブラウザにドラッグ&ドロップするだけ。Git不要 |
| ファイルを渡すだけ | `dist/PinRoute.html` の1ファイルを送る。受け取った人はダブルクリックで開ける |

## 外部サービスの利用条件

一般公開するにあたって確認した内容。

| サービス | 公開利用 | 条件 |
|---|---|---|
| 地理院タイル(地図) | 可 | 出典の記載のみ。レート制限の定めは公表されていない |
| 国土地理院 AddressSearch(住所検索) | 可 | 出典の記載 |
| Nominatim(施設名検索) | 条件付きで可 | **アプリ全体で1req/秒**、**結果のキャッシュ必須**、利用者数が中程度であること |
| OSRM デモサーバー(ルート計算) | **不可** | 「非商用かつ合理的な用途に限る」。公開ビルドでは使わない |

これに合わせて次のようにしている。

- 地図タイルは**地理院タイル(淡色地図)**を使う。国内向けで色が薄く、ピンや情報ブロックが見やすい
- 検索結果は `src/geocache.ts` で**ブラウザに保存**し、同じ言葉を外部に問い合わせ直さない(30日・最大300件)
- Nominatimは**国土地理院で答えが出ないときだけ**呼ぶ。完全一致(「東京駅」)や住所らしい入力(「大阪市北区梅田1-1-3」)では呼ばない
- ルート計算は公開ビルドに含めない

## 検索の仕組み(重要)

国土地理院のAddressSearch APIは**関連度順に並んでいない**。
たとえば「東京駅」で検索すると53件返るが、先頭は

```
北海道札幌市東区 / 北海道東神楽町東 / 北海道佐呂間町東 / …
```

のように「東」の部分一致が並び、本命の「東京駅」は配列の**末尾**に来る。
さらに施設名には弱く、「札幌市時計台」では「北海道札幌市」しか返さない。

そのためこのアプリでは、取得したあとに `src/rank.ts` で並べ替える。

1. **正規化** — 全角/半角、大小文字、`一丁目9番1号` と `1-9-1` の表記ゆれを吸収する
2. **一致度の採点** — 完全一致 `1.00` > クエリを丸ごと含む `0.85〜0.99` > 部分一致 `0〜0.80`
3. **並べ替え** — 一致度を最優先。同点なら 施設・駅 > 市区町村レベルの住所、さらに Nominatim の著名さ(importance)で決める
4. **重複統合** — 同名かつ5km以内は1件にまとめる。名称が違っても250m以内なら同じ場所とみなす。同名でも離れていれば別地点として残す(各地の「富士山」)
5. **足切り** — 最良候補から0.35以上劣る候補は表示しない。本命が決まっているときに迷わせないため

また、国土地理院とNominatimは**順に問い合わせて統合**している。

| 状況 | 動作 |
|---|---|
| 国土地理院が有効な候補を返した | Nominatimを補完として使う。残り時間だけ待ち、間に合わなければ得られた分で返す |
| 国土地理院が0件/通信失敗 | Nominatimを最大8秒まで待つ |
| 両方とも通信失敗 | エラー(E2)を表示 |

Nominatimへのリクエストは1秒1回以下に制限している(NFR-04)。
まとめて入力のように何十件も続けて調べるときは、国土地理院で足りていればNominatimを呼ばない。

住所に郵便番号や建物名が付いていても取り込めるよう、見つからなかったときは
順に切り詰めて調べ直す(`buildQueryVariants`)。

| 入力 | 試す順 |
|---|---|
| `〒160-0023 東京都新宿区西新宿2-8-1` | そのまま → 郵便番号を除く |
| `東京都杉並区高円寺南4-26-8 サンライズマンション101` | そのまま → 末尾の建物名を落として住所部分だけ |

候補の下に出る「東京都千代田区」などの所在地は、国土地理院の
市区町村コードを `src/muni.ts` の対応表で地名に変換したもの
(出典: 国土地理院「地理院地図」muni.js)。同名の候補を見分けるために使う。

## 構成

```
src/
├── main.ts       起動・イベント配線
├── state.ts      ピン一覧の状態(純粋関数)
├── rank.ts       検索候補の正規化・採点・重複統合(純粋関数)
├── bulk.ts       貼り付けた表の読み取りと列の推定(純粋関数)
├── appearance.ts 色・大きさの定義と解決(純粋関数)
├── geocache.ts   検索結果の保存(Nominatimの規約が求めるキャッシュ)
├── config.ts     ビルドごとの設定(ルート計算の有無)
├── callout.ts    地図上の情報ブロックと引き出し線
├── muni.ts       市区町村コード→地名の対応表(生成物)
├── geocode.ts    国土地理院 / Nominatim 呼び出し + パーサ
├── route.ts      OSRM 呼び出し + パーサ
├── share.ts      共有URLのエンコード/デコード
├── storage.ts    localStorage 読み書き
├── mapview.ts    Leafletラッパー(マーカー・ルート線)
├── ui.ts         パネルのDOM描画
├── throttle.ts   debounce / rateLimit
└── style.css

docs/
├── manual.html             図解付き操作マニュアル(画像を埋め込んだ1ファイル)
├── manual.template.html    その原稿。画像は {{名前}} で差し込む
├── how-it-works.html       仕組みの解説(初学者向け・図解。外部依存なしの1ファイル)
├── git-and-github.html     GitとGitHubのきほん(初学者向け・図解)
├── sample-properties.csv   まとめて入力を試すためのサンプル(神保町駅500m圏の10件)
└── images/                 マニュアル用スクリーンショット(自動生成)

scripts/
├── smoke-live.mjs     実ブラウザ+実APIでの疎通確認
└── capture-manual.mjs マニュアルのスクリーンショット撮影と生成
```

`state.ts` / `rank.ts` / `bulk.ts` / `appearance.ts` / `share.ts` / `throttle.ts` と各パーサは副作用のない純粋関数で、
fetch・DOM・Leafletへの依存は通信層とビュー層に閉じている。

## 使用している外部サービス

| 用途 | サービス | 備考 |
|---|---|---|
| 地図タイル | 地理院タイル(淡色地図) | z4〜18で配信。19以上は18を引き伸ばす。日本国内のみ |
| ジオコーディング | 国土地理院 AddressSearch | 日本の住所に強い |
| ジオコーディング | Nominatim | 施設名に強い。必要なときだけ呼び、結果は保存する |
| ルート計算 | OSRM デモサーバー | **手元用の1ファイル版のみ**。稼働保証なし。失敗してもピン機能は継続 |

いずれも無料・APIキー不要。Googleマップは通常のリンク遷移のみで、APIは使用していない。
